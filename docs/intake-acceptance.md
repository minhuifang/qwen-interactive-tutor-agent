使用 qwen3.7-plus，通过真实页面提交两份自编“合并区间”文本。均返回 HTTP 200 并通过解析协议校验。测试在独立无界面 Chromium 中执行，未修改用户预览页中的草稿，也未读取或输出密钥。

| 请求 | 结果 | 输入 / 输出 / 合计 Token |
| --- | --- | --- |
| 完整题 | 保留闭区间、端点接触也合并、按起点升序、无需原地修改、输入范围及原样例；无待澄清项 | 388 / 249 / 637 |
| 缺失信息题 | 输入输出说明留空，约束和样例为空；询问输入格式、合并规则、数据范围，没有猜测内容 | 289 / 141 / 430 |

两次真实调用合计 1067 Token，后续失败路径使用模拟响应，未新增调用。

## 页面验收

- 完整题仍必须勾选人工核对才能确认。
- 确认后的 Problem 保留原文，source 为 qwen，未包含 solution。
- 编辑标题会撤销确认并取消核对勾选。
- 清空期望输出，即使重新勾选核对也无法确认；补回后可以重新确认。
- 修改原文并解析新题，旧确认被清除。
- 缺失信息题不能直接确认。
- 模拟解析失败时保留原文和上次草稿。
- 无页面运行时异常。

## 复现与边界

脚本为 `tests/live-intake-check.mjs`，不包含在 `pnpm test` 中。运行前需要已启动的 localhost:3001、配置好的模型与明确的调用预算授权。需设置 PLAYWRIGHT_PACKAGE_ROOT 和可选 PLAYWRIGHT_CHROMIUM_EXECUTABLE，与 live-ui-check.mjs 一致。

脚本默认执行两次真实解析，没有缓存；失败后再次运行可能重新消耗额度，不能无意识循环重跑。

当前验收覆盖代表性输入，不证明所有题目都能被准确理解。人工核对仍然必要。尚未实现新题解法、隔离执行、测试结果诊断及动画生成。下一阶段应先建立解题结果协议，再接入无密钥、禁网络、有资源限额的隔离验证环境；不能把 Node VM 当作运行不可信代码的安全边界。
