它不是一次写对，而是跑一次、读失败、再改一次。

下面这道「两数之和」，Agent 前两轮都没通过：第一次返回了数值本身而不是下标，第二次在重复元素上把同一个下标用了两次。 每一轮它都拿到了容器里的真实执行结果，第三轮才通过。轨迹是这条链路逐步产生的，没有人工补写。

执行轨迹 演示轨迹 · 脚本化策略 + 模拟执行

这条链路在做什么

模型只被允许调用两个工具：run_tests 在禁网只读容器里执行代码，finish 提交答案。它拿不到执行权，也拿不到「通过」的定义权。

为什么结论可信

「通过」由执行器逐例比较 JSON 得出。模型说通过但执行没过，界面显示的是执行结果；提交的代码如果没跑过，会强制补跑一次。

怎么自己跑

pnpm install && pnpm dev，配置 DEEPSEEK_API_KEY，再 colima start tutor-sandbox。没有 Docker 时页面自动退化为轨迹回放。

说明：本页展示的是回放轨迹，由真实循环代码 + 脚本化策略 + 模拟执行结果生成，用于演示交互与协议，不是一次真实模型运行。 真实运行需要本地 Docker 沙箱与模型密钥，实测数据请见 README 的评测章节；未跑过的评测不会写成通过率。
