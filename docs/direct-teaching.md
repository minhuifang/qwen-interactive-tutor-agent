# 直接教学（2026-09-12）

## 2026-09-13：默认入口已改为单次流式教学

以下 09-12 的两阶段说明仅为历史记录。现在页面使用 `StreamTeaching`，`/api/teach` 指向 `stream-teacher.ts`：原题直接进入一次 Qwen 文本流，不经过 parser、confirmationIssues 或 solutionSchema。不再因为内部标题、输入输出字段、assumptions 缺失阻止讲解。非空题目即可开始，最多 6000 字符；不再有 20 字符下限。只有影响答案的实际矛盾才由老师在讲解中提出具体问题，可在页面自然语言回答或继续追问。

教学不强制生成完整代码，不需要 JSON 教学结构；SSE 仅作为传输协议解析。服务端转成 meta/delta/done/error 文本流，客户端收到增量立即显示。只有正常结束才标记完成，断流/超时/取消保留部分内容。主流式调用单并发、每进程每小时 12 次（失败也计数）、90 秒期限，不自动重试；点击停止和切换工作区向上游发送取消，但不保证上游停止计费。传输与输出大小仍有限制。原题修改撤销旧内容，重新讲解保留旧轮次。长对话只带最近 30000 字符讲解上下文，原题始终单独传递。

TTS 在文字停止变化后点击收听，按段合成，只显示最新一轮的收听控制，避免多段同时发声。参考代码是独立可选调用，从原题与对话直接生成，仍有针对运行器的格式校验及一次修复；失败不移除文字教学。验证器没有自动提取新题样例，用户可填写输入/预期并确认后运行。旧手动整理入口保留，旧 teach.ts 与 direct-teaching.tsx 不再连接默认页面路由。

验证：48 项自动测试、类型检查与最终构建通过，新增原文三数之和直达一次流式调用、首段早于结束、UTF-8 跨包、SSE CRLF/多行、断流保留、取消传播、超时释放和额度保护。真实调用用户三数之和原文：首文本 1393ms，结束 22425ms，560 个 delta，2294 Token；返回排序、双指针、去重与教学示例，无补充范围要求，未执行代码。随后补充默认 JavaScript 片段提示，未再次消耗额度。浏览器交互/TTS 听感尚未验收，模型讲解的全部语义不因此获证。保持本地，不发布。

传输依据：[百炼官方流式输出文档](https://www.alibabacloud.com/help/en/model-studio/stream)。

## 历史：两阶段教学实现

默认入口改为“直接讲题”：输入原文，点击“开始讲解”，服务端 `/api/teach` 自动串联题意整理与解法生成。不再要求勾选、确认题意、再点击生成。原来的手动核对流程在可选折叠入口中保留。

题意解析提示词不再要求因缺少非必要范围、样例而提问。关键歧义仍返回问题，用户用一段自然语言补充后继续。系统准备的题目标记 `status: ready`，没有伪造人工确认。语义是否明确仍依赖模型判断，不保证永不误问。主流程仍有两次串行模型调用，尚非流式输出。

讲解优先显示核心思路与步骤推演，参考代码、复杂度、样例运行收进可选内容。新增新题讲稿 TTS，点击才调用，步骤高亮随语音推进，不是自动生成算法状态动画。修改题目、切换工作区撤销等待和音频；工作区切换保留题目与已有结果，刷新会丢失。客户端停止不保证停止上游计费。

`assumptions` / `cautions` 非空字符串可无损包装为数组；不擅自删除、截断、清空或转换对象。其他解法 JSON / schema 异常将原输出与安全校验原因回传模型，最多修复一次，仍需严格校验。网络、鉴权、截断、超时不重试。修复计入同一小时 12 次预算，成功响应累计两次解法 Token；题意解析用量目前不在 UI 合计。整个解法阶段共用 90 秒期限，题意解析仍为 45 秒，主入口客户端等待上限 150 秒，修复不会无限延长请求。真实联调曾触发旧的 45 秒解法期限，因此调长并同步调整旧入口等待上限。

41 项自动测试通过，包含无范围/样例题意自动继续、关键歧义不调用解法、假设字符串无损整理、格式修复与用量累加、失败只修复一次及旧安全回归。类型检查与构建通过。代码始终标记未运行，运行仍需要用户主动核对并授权。保持本地服务，不部署公网。

真实联调：首次合并区间在旧解法期限内超时；调整后第二次返回 HTTP 200 / ready，耗时 40.178 秒，生成核心思路和 8 步推演，解法用量 3018 Token（不含题意解析和失败调用）。未要求补充范围或确认。未执行生成代码，未做浏览器交互或 TTS 听感验收。模型“输入非空，如果为空返回空数组”的假设措辞仍不严谨，流程成功不等于讲解语义已全面验证。
